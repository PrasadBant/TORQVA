# Wi-Fi setup for the current ESP32-S3 build

This setup uses the board's existing USB port once. It stores the SSID, password, backend HTTPS address and CA in ESP32 NVS. The password is not an API response or telemetry field. The current firmware supports one provisioned network; changing networks requires reprovisioning NVS over USB. Website provisioning, automatic network switching, static IP and mDNS discovery are not implemented.

1. Choose the PC's LAN IPv4 address reachable from the ESP32 on the same router or hotspot. The address must not be `127.0.0.1`. In `backend`, create a development TLS certificate with `python scripts/development/ota_https_gateway.py make-cert --ip <LAN_IP> --out-dir <private_directory_outside_repo>`. Keep the CA key and server key private.
2. Generate the per-device key: `python scripts/setup/provision_device_key.py --device-id RIG-1 --out-dir <empty_private_directory>`. It writes a backend key record and a secret NVS CSV. Back up the backend key record privately.
3. Generate Wi-Fi NVS data: `python scripts/setup/provision_ota.py --ssid <SSID> --base-url https://<LAN_IP>:8443 --ca <cert_dir>/bench_ca.pem --out-dir <another_empty_private_directory>`. The tool prompts for the password rather than accepting it as a command argument.
4. Combine the two NVS CSV files into one: retain one `key,type,encoding,value` header, then the `torqva` namespace and `authkey` row, then the `torqva_ota` namespace and its `ssid`, `pass`, `base`, and `ca` rows. Keep the combined CSV private. Generate the NVS image with `python -m esp_idf_nvs_partition_gen generate <combined.csv> <nvs.bin> 0x5000` after installing `esp-idf-nvs-partition-gen`.
5. With motor power disconnected, flash compatible firmware and the NVS image over USB. The pinned partition table places NVS at `0x9000`: `python -m esptool --chip esp32s3 --port <COMx> write_flash 0x9000 <nvs.bin>`. Preserve the complete partition layout when flashing firmware for the first time. Delete the temporary CSV and NVS image after confirming the board works.
6. Set backend `TORQVA_DEVICE_LINK=1`, `TORQVA_OTA_PUBLIC_BASE_URL=https://<LAN_IP>:8443`, and `TORQVA_OTA_PUBLIC_KEY=<release_public_key.pem>`. Run the backend and TLS gateway (`python scripts/development/ota_https_gateway.py serve --ip <LAN_IP> --cert <cert_dir>/gateway_cert.pem --key <cert_dir>/gateway_key.pem`). Allow the ESP32 to reach port 8443. The gateway forwards device traffic to the local backend.
7. Power the ESP32, then disconnect its USB data cable while keeping suitable power. The device connects outward over TLS and appears as the active Wi-Fi transport only after the TORQVA protocol and per-device key handshake succeed.

The board needs a firmware image built with the same public release key (`python scripts/build/sign_firmware.py export-header --pub <release_public_key.pem>` before building). Without a public key, `ota_info` reports that OTA is unavailable. Use the existing USB recovery procedure if Wi-Fi credentials, CA or backend address change.
