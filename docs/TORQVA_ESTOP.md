# E-stop design (owner decision; NOT installed, NOT verified)

**Firmware monitoring input (implemented, software only):** GPIO 15, normally-closed contact between GPIO 15 and GND, internal pull-up. Healthy (closed) reads LOW. A pressed switch, a broken wire, an unconnected input or an unread pin is an emergency-stop condition (`estop.h`, debounce 100 ms on release, assertion immediate). The state is reported in every status frame (`es`: 0 not monitored, 1 asserted, 2 released, 3 unknown) and shown on the dashboard.
**It is monitoring only.** The ESP32 GPIO must never be the only thing that stops the motor. Required, independent of the ESP32: an appropriately rated E-stop switch/contactor (NC contacts, positive opening) that removes motor-driver power (the supply feeding the BTS7960), wired so that a broken wire or a de-energised contactor means no power. Use suitable switching hardware rated for the supply voltage and stall current. Add a second NC contact of the same device to GPIO 15.
**Firmware enforcement is OFF by default.** The build flag `-DTORQVA_ESTOP_INPUT_WIRED=1` (declaration that the circuit is installed and verified) is intentionally not set anywhere. Until it is, the start interlock refuses with `ESTOP_INPUT_NOT_VERIFIED`, the input is only reported, and nothing latches on it (an unwired input floats HIGH). When the flag is set, an asserted/unknown input stops the motor and latches `EXTERNAL_ESTOP`.
**Board verification still required (this software cannot do it):** GPIO 15 is a plain GPIO on the ESP32-S3 but is also the 32 kHz crystal pad `XTAL_32K_P`; confirm on the actual board schematic and header that no 32 kHz crystal or other circuit uses it, and that the final pin map has no conflict.
**Verification steps for the human, in order:** (1) wire the contact and the independent power-removal circuit with the motor supply and driver disconnected; (2) confirm LOW when closed and HIGH when open with a meter; (3) confirm the dashboard shows `E-stop input: released` closed and `asserted` for press, wire removal and disconnected input; (4) with the driver unloaded, confirm pressing it removes driver power independently of the ESP32; (5) record the evidence in Safety & Commissioning; (6) only then set `TORQVA_ESTOP_INPUT_WIRED=1`, rebuild and flash.
